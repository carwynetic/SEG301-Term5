## 1. Web Crawling – Cơ chế thu thập dữ liệu Web

### 1.1. Thách thức cơ bản (Challenges)
* **Sheer scale**: Hàng chục tỉ trang web, liên tục tăng trưởng và thay đổi.
* **Lack of control**: Công cụ tìm kiếm không kiểm soát máy chủ web và nội dung của bên thứ ba.

### 1.2. HTTP Protocol & URLs trong Crawling
* **URL (Uniform Resource Locator)**: Định danh duy nhất cho tài nguyên web (gồm *scheme*, *host*, *path*).
* Các phương thức HTTP quan trọng:
  * **`GET`**: Tải toàn bộ nội dung tài nguyên/trang web (dùng phổ biến nhất).
  * **`POST`**: Gửi dữ liệu lên máy chủ (thường dùng cho biểu mẫu, giao dịch; crawler hiếm khi đào sâu vào POST).
  * **`HEAD`**: Chỉ lấy phần **HTTP Header** (không tải body), dùng để kiểm tra thông tin thay đổi (`Last-Modified`, `Content-Length`) nhằm tiết kiệm băng thông.

### 1.3. Kiến trúc Web Crawler
* **Frontier (Request Queue)**: Hàng đợi lưu trữ danh sách các URL đã được phát hiện nhưng chưa được tải về.
* **Multi-threading (Đa luồng)**: Bắt buộc phải có để tránh lãng phí tài nguyên CPU do độ trễ mạng mạng cao:
  * Chờ phân giải tên miền (**DNS Resolution**).
  * Chờ thiết lập kết nối (**TCP Handshake**).
  * Chờ máy chủ phản hồi dữ liệu (**Server Response Latency**).
* **Politeness Policies (Chính sách lịch sự)**:
  * Tránh tấn công DoS/làm sập máy chủ mục tiêu.
  * Không tải nhiều hơn 1 trang cùng lúc trên một web server.
  * **Crawl Delay**: Giãn cách giữa 2 yêu cầu liên tiếp đến cùng một server (vài giây đến vài phút).
  * Phân chia logic của Request Queue: **Single queue per web server** (mỗi máy chủ có một hàng đợi riêng).
  * Tuân thủ quy tắc từ tệp `robots.txt` (Robots Exclusion Protocol).

### 1.4. Độ tươi mới (Freshness) & Tần suất Crawl lại
* **Freshness & Age**: Trang web liên tục được thêm, sửa, xóa. **Age** là chỉ số đo lường thời gian trôi qua kể từ khi trang web thay đổi cho đến khi crawler cập nhật lại.
* Tối ưu hóa: Dùng **HTTP `HEAD` request** để kiểm tra `Last-Modified` hoặc `ETag`, nếu chưa đổi thì không cần tải lại (`HTTP 304 Not Modified`).

### 1.5. Kỹ thuật Crawling nâng cao & Bóc tách vùng ẩn
* **Focused Crawling (Topical Crawling / Vertical Search)**:
  * Chỉ thu thập các trang thuộc một chủ đề cụ thể (e.g., phim ảnh, y tế, tin tức).
  * Độ chính xác (*Accuracy*) của Vertical Search cao hơn General Search do không bị nhiễu bởi các tài liệu ngoại lai (**Extraneous information**).
  * Cách tiếp cận hiệu quả: Dùng mô hình phân loại tự động để quyết định URL nào trong Frontier đáng để đi tiếp, thay vì crawl toàn bộ web rồi lọc bỏ.
* **Deep Web (Hidden Web)**: Các trang mà crawler thông thường không tìm thấy qua liên kết Hyperlink:
  * **Private sites**: Cần đăng nhập/xác thực tài khoản.
  * **Form results**: Dữ liệu nằm sau các biểu mẫu tìm kiếm cơ sở dữ liệu.
  * **Scripted pages**: Dữ liệu được tải động bằng JavaScript / AJAX / SPA (Single Page Application).
* **Sitemaps**: File XML do chủ website cung cấp để khai báo danh sách URLs, `Modification time`, `Modification frequency`, và `Priority`.

## 2. Desktop Crawling & Document Feeds

### 2.1. Crawling tài liệu và Email (Desktop Search)
* Thu thập dữ liệu trên máy tính cá nhân (Email, Word, Excel, PDF).
* Thách thức đặc thù so với Web Crawling:
  * **Update speed**: Đòi hỏi cập nhật tức thì (người dùng vừa lưu file là phải tìm kiếm được ngay).
  * **Disk space**: Dung lượng ổ cứng và tài nguyên máy tính cá nhân bị giới hạn.
  * **Data privacy / Security**: Đảm bảo quyền riêng tư và phân quyền truy cập nghiêm ngặt.

### 2.2. Document Feeds (Nguồn cấp dữ liệu)
* Dòng tài liệu xuất bản được sắp xếp theo trình tự thời gian từ một nguồn.
* Hai cơ chế:
  * **Push feed**: Máy chủ chủ động gửi thông báo/nội dung ngay khi có tài liệu mới đến các subscriber.
  * **Pull feed**: Phía người nhận định kỳ truy vấn kiểm tra xem có tài liệu mới hay không.
  * Tiêu chuẩn thông dụng: **RSS** (*Really Simple Syndication* / *Rich Site Summary*), **Atom**.

## 3. Mã hóa ký tự (Character Encodings) & Lưu trữ (Document Storage)

### 3.1. Character Encodings (Vấn đề chuyển đổi)
* Văn bản hiển thị bằng các ký tự/hình ảnh nhỏ gọi là **Letters** hoặc **Glyphs**.
* **Character Encoding**: Bảng ánh xạ giữa chuỗi bit nhị phân và các Glyphs.
  * **ASCII**: Chuẩn 1 byte (7-8 bit) cho ký tự tiếng Anh cơ bản.
  * **CJK**: Chuẩn đa byte (thường 2 bytes) cho tiếng Trung, Nhật, Hàn (Big5, Shift-JIS, GB2312).
  * **Unicode (UTF-8, UTF-16)**: Chuẩn phổ quát hỗ trợ tất cả các ngôn ngữ.

### 3.2. Yêu cầu của hệ thống lưu trữ tài liệu (Document Storage)
1. **Random access (Truy cập ngẫu nhiên)**: Cực kỳ quan trọng để truy xuất nhanh nội dung tài liệu phục vụ sinh đoạn trích tóm tắt (**Snippet generation**) trên trang kết quả tìm kiếm (**SERP**). Thường tra cứu thông qua **URL Hashing**.
2. **Compression (Nén dữ liệu)**: Giảm chi phí lưu trữ khổng lồ.
3. **Updating (Cập nhật)**: Hỗ trợ ghi/cập nhật tài liệu mới linh hoạt.

### 3.3. Kiến trúc lưu trữ phân tán: BigTable (Google)
* Thiết kế cho quy mô web cực lớn (*Very largest document collections*).
* Cấu trúc: Bảng khổng lồ chia thành nhiều mảnh nhỏ gọi là **Tablets**, phân phối trên hàng ngàn máy chủ.
* Không dùng ngôn ngữ truy vấn quan hệ phức tạp (No SQL/No complex joins), chỉ hỗ trợ **Row-level transactions** (Giao dịch cấp hàng) dựa trên khóa: `(row:string, column:string, time:int64) -> string`.

## 4. Tiền xử lý dữ liệu: Deduplication & Noise Removal

### 4.1. Xóa tài liệu trùng lặp (Delete Duplicates)
Nguyên nhân trùng lặp: Nhiều URL trỏ về cùng một nội dung (URL Aliases, session IDs), trang nhân bản (**Mirror sites**), nội dung trích dẫn lại.

#### A. Exact Duplicates (Trùng khớp tuyệt đối)
* Dùng kỹ thuật kiểm tra mã băm: **Checksumming / Hashing** (e.g., MD5, SHA-1, CRC).
* Bất kỳ tài liệu nào có cùng nội dung ký tự sẽ sinh ra cùng một giá trị checksum.

#### B. Near-Duplicates (Gần trùng lặp)
* Khó phát hiện hơn: Hai trang có nội dung chính giống nhau nhưng khác nhau về ngày tháng, quảng cáo đính kèm, định dạng hoặc thanh điều hướng (ví dụ: trùng > 90% từ).
* Hai kịch bản xử lý (**Scenarios**):
  * **Discovery scenario**: Chạy trong quá trình crawl/index để loại bỏ trang trùng trước khi lập chỉ mục (tiết kiệm không gian lưu trữ và tài nguyên tính toán).
  * **Search scenario**: Chạy tại thời điểm truy vấn để gộp cụm kết quả trùng lặp hiển thị cho người dùng.
* Quy trình tạo **Fingerprints** (Dấu vân tay tài liệu):
  1. **Tokenization / Normalization**: Tách từ, loại bỏ dấu câu, HTML tags, khoảng trắng.
  2. **N-grams (Shingles)**: Nhóm các từ liên tiếp thành các cụm $n$ từ (thường là các chuỗi trượt gối đầu nhau - *overlapping sequences*).
  3. **Selection**: Chọn ra một tập con $n$-grams đại diện cho tài liệu.
  4. **Hashing**: Băm các $n$-grams đã chọn thành các số nguyên ngắn.
  5. **Storage**: Lưu các giá trị hash vào **Inverted Index** để so khớp nhanh độ tương đồng (thường dùng chỉ số đo như **Jaccard Similarity**).

### 4.2. Khử nhiễu (Remove Noise / Content Extraction)
* **Noise (Rác/Nhiễu giao diện)**: Banners, quảng cáo (Ads), hình ảnh trang trí, menu điều hướng (**Navigation links**), chân trang (Footer), điều khoản dịch vụ (ToS).
* Thực tế: Nội dung chính (**Content block**) thường chiếm **ít hơn 20%** diện tích hiển thị của trang web.
* **Thuật toán mật độ Text vs Tag (Token Distribution Algorithm)**:
  * Mô hình hóa trang web thành một chuỗi nhị phân (bit sequence):
    $$\text{bit} = 1 \text{ (nếu token thứ } n \text{ là HTML tag)}, \quad 0 \text{ (nếu là từ/text token)}$$
  * Tìm 2 vị trí ranh giới $i$ và $j$ sao cho:
    * Tối đa số lượng thẻ tag trước vị trí $i$ và sau vị trí $j$.
    * Tối đa số lượng token văn bản (non-tag tokens) nằm trong khoảng giữa $[i, j]$.
    * Khoảng $[i, j]$ này chính là vùng chứa nội dung bài viết chính (**Main Content Block**).

## BẢNG TỔNG KẾT KEYWORDS PHỤC VỤ THI CỬ (CHEAT-SHEET)

| Thuật ngữ (Keyword) | Bản chất / Khái niệm cốt lõi |
| :--- | :--- |
| **Frontier / Request Queue** | Hàng đợi chứa các URL được phát hiện, chờ crawler lấy về. |
| **Politeness Policy** | Quy tắc giãn cách request (crawl delay), mỗi domain 1 queue, tránh sập server. |
| **HTTP `HEAD` Request** | Request chỉ lấy header, kiểm tra `Last-Modified` để tính toán độ tươi mới (**Freshness/Age**). |
| **Focused Crawling** | Crawler chuyên biệt theo chủ đề cho máy tìm kiếm dọc (**Vertical Search**). |
| **Deep Web / Hidden Web** | Vùng dữ liệu không đến được qua link tĩnh: đằng sau forms, mật khẩu, Javascript/SPA. |
| **Push vs Pull Feeds** | Push (server chủ động bắn tin); Pull (client chủ động định kỳ kiểm tra qua RSS/Atom). |
| **Random Access** | Yêu cầu lưu trữ tài liệu để truy xuất tức thì phục vụ sinh **Snippet** dựa trên URL Hash. |
| **BigTable** | Hệ cơ sở dữ liệu phân tán NoSQL của Google, phân chia thành các **Tablets**. |
| **Exact Duplicate** | Phát hiện trùng khớp tuyệt đối bằng **Checksum / Hash function**. |
| **Near-Duplicate** | Gần trùng khớp; phát hiện bằng **Fingerprinting** qua **overlapping n-grams / shingles**. |
| **Discovery vs Search Scenario** | Deduplication ở lúc crawl/index (Discovery) vs lúc trả kết quả truy vấn (Search). |
| **Token Distribution Algorithm** | Chuỗi bit (1 cho Tag, 0 cho Non-tag), tối ưu khoảng $[i, j]$ để trích xuất khối nội dung chính. |
